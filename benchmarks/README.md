# Benchmark publication

Tracker: #10

IDKMesh keeps benchmark definitions, attached evidence, and the derived public
summary in this directory. The publication path is deliberately deterministic:
readers should be able to reproduce the public snapshot from the same commit
without trusting prose maintained by hand.

## Canonical current view

- [`PUBLICATION.md`](PUBLICATION.md) is the human-readable derived summary.
- [`publication.json`](publication.json) is the machine-readable form of the
  same derived state.
- each `*/cohort.json` is a versioned benchmark cohort governed by
  [`docs/specifications/BENCHMARK_COHORT_V0_1.md`](../docs/specifications/BENCHMARK_COHORT_V0_1.md).

Both publication files are generated by
[`tools/benchmark_publication.py`](../tools/benchmark_publication.py). Regenerate
them after a cohort/evidence change with:

```bash
PYTHONPATH=. python tools/benchmark_publication.py
```

Check that the committed copies are reproducible without rewriting them with:

```bash
PYTHONPATH=. python tools/benchmark_publication.py --check
```

The benchmark cohort contract workflow runs that check for relevant pull
requests and protected-main changes.

## Automated public snapshots

`.github/workflows/benchmark-publication.yml` publishes the two canonical files
as a GitHub Release after a relevant change reaches `main`. Publication is
commit-bound and fail-closed:

1. the workflow checks out the exact event commit;
2. it installs only the benchmark contract dependency;
3. it runs the deterministic publication drift check and publication tests;
4. only then does it create `benchmark-cohort-<full-main-sha>`;
5. the release contains the committed Markdown and JSON files byte-for-byte;
6. an existing tag is accepted only when it already points at that exact commit;
   tags are never force-moved or reused for a different revision.

Pull-request events cannot invoke the write-capable publication workflow. PRs
are validated by the separate read-only benchmark contract workflow instead.
A manual dispatch is also constrained to `main` by the publication job guard.

This makes releases durable distribution/provenance surfaces while the checked-in
files remain the canonical source for the current repository revision.

## Scientific boundary

Publication does **not** turn a benchmark observation into stronger evidence.
The workflow does not execute candidates, choose outcomes, compute a new score,
or select a preferred configuration. It republishes only what the committed
cohort/evidence contracts already justify.

In particular, the current generated publication must be read with its own
stated limitations. A small number of verified observations, observations from
one structural signature, or a benchmark with no observed failures do not by
themselves establish comparative superiority, diversity benefits, statistical
power, or generalization to real-world workloads. Those claims require the
prospective experimental designs and evidence described by the corresponding
research protocols.

## Change discipline

When changing cohort definitions or attached evidence:

- preserve frozen pre-outcome commitments and immutable source revisions;
- regenerate `PUBLICATION.md` and `publication.json` in the same change;
- run the benchmark publication tests;
- do not edit generated publication prose to obtain a desired conclusion;
- treat a failed publication workflow as an evidence/provenance failure to
  investigate, not a reason to bypass the check or retarget an existing tag.
