# Pull Request Triage — 2026-08-28

**Repository:** `MSKazemi/idkmesh`  
**Purpose:** reduce integration debt professionally while preserving evidence, project memory, safety gates, and useful parallel research.

## Maintainer principles used

This triage did **not** optimize for closing or merging the largest number of PRs. It optimized for coherent integration.

Rules applied:

1. **Exact artifact before description.** Review the actual changed files/diff and exact-head CI; do not merge based on PR prose alone.
2. **Dependency order.** Merge foundational safety/contracts before stacked feature work.
3. **No stale-stack merges.** If squash/integration changes ancestry, rebuild a clean replacement on current `main` rather than forcing a stale stack.
4. **Evidence gates remain binding.** Draft/runtime-gated work stays draft even when unit CI is green.
5. **Preserve negative evidence.** Failed CI/runtime experiments are retained and explained; they are not rewritten as success.
6. **Convergence over proliferation.** Close parallel controllers/duplicate architectures once a canonical path exists.
7. **Archive before closing stale history.** Conversation-only PRs are preserved on `main` before stale PR closure.
8. **Separate unrelated concerns.** PRs combining independent research/product/memory concerns should be split before review-ready status.
9. **No automation self-authorization.** A workflow/controller cannot infer acceptance, approval, or merge authority from its own success.
10. **Draft means genuinely blocked.** Remaining open PRs should have explicit conditions for becoming review-ready.

## Definition of a healthy PR queue

IDKMesh should prefer:

- a few review-ready PRs with exact-head green evidence;
- drafts with explicit blockers;
- clean replacement PRs instead of ancestry gymnastics;
- closed superseded branches that remain available as provenance;
- one canonical implementation per responsibility;
- negative evidence retained alongside positive evidence.

A useful integration-health metric is not PR count. A better direction is:

```text
IntegrationYield =
  verified durable changes merged
  ---------------------------------------------
  reviewer attention + conflict debt + rework
```

with separate penalties for stale review-ready PRs, duplicate responsibility, unverified privileged workflows, and misleading description/diff mismatches.
