**Source baseline:** `main@0cdf0519dd937f04a4e0a98d077719b659f0e5d6` (2026-10-13); 61 direct workflow YAML files. This catalog is a **configuration inventory**, not an audit of runner isolation, the security of third-party actions, external service availability, or an assertion that any scheduled run succeeded. Inspect the linked workflow YAML for the operative `if`, `paths`, `secrets`, checkout `ref`, and job conditions before taking action. The [repository PR Gate](https://github.com/MSKazemi/idkmesh/blob/main/.github/workflows/pr-gate.yml) remains the required merge-safety check; path-filtered workflows are supplemental, and a green check is not human acceptance.

## Three boundaries not to confuse

1. **Trigger** is the *event family* declared under `on:`, not evidence the job runs for every event. Path filters, job conditions, secrets, concurrency, and external prerequisites also matter.
2. **GitHub write scopes** are the union of *explicit* workflow/job `permissions: ...: write` declarations, not observed writes or an authorization certificate. The entry `none` means no explicit GitHub write scope, **not** no network or side effects. A workflow may call a provider with a separately supplied secret, run controlled Docker code, or send IndexNow notifications while its GitHub token remains read-only.
3. **Evidence is not integration.** Executable tests, GitHub release assets, generated reports, provider completion and simulated acceptance do not independently grant permission to merge. An approved and exact-head reviewed PR remains the integration path.

## Operational trust checklist

- **Review and merge:** `pr-gate.yml` runs the unfiltered unit tier and contract/link checks for both supported Python versions; the [testing guide](../TESTING.md) explains what it excludes. Never substitute a path-filtered research workflow for this gate, nor count `workflow_dispatch` availability as evidence a task was executed.
- **GitHub writers:** `ace-cohort-observer.yml`, `ace-community-growth.yml` and `issue-model-router.yml` declare issue-write; `jules-dispatch.yml` declares issue-write plus external Jules calls; `auto-draft-pr.yml` declares pull-request-write; `benchmark-publication.yml` declares contents-write. Check trusted checkout scope, conditions and policy before running these workflows. No such job may be treated as human approval.
- **Publications:** `publish-pypi.yml` uses tag identity, short-lived OIDC, an environment requiring owner configuration/review, build attestations and release-upload privileges. `indexnow-discovery.yml` sends public URLs to an external endpoint, not a ranking outcome; Scorecard/CodeQL upload security analyses.
- **Agent and real-code execution:** Jules dispatch is label-governed, OpenHands is an explicitly dispatched pilot, and the `real-*-e2e.yml` workflows run pinned candidates in a controlled Docker host. They do **not** make a general-purpose untrusted-code runner safe to run on a developer machine.
- **Advisory research:** synthetic `sim/`, `randomness_lab/`, ACE and portfolio jobs may upload artifacts or use external public metadata, but their outputs do not change the canonical capability/evidence classification without independent review.
